# AGENTS.md — Ortho : Intelligent Finances

Flutter/Dart finance tracker (`pubspec` package name is `financetracker`). Local-first SQLite with a
CQRS-style command/query bus, plus optional Supabase sync. Dark fintech UI per `DESIGN.md`.

## Commands

```bash
flutter pub get
flutter analyze          # the only static check; must be clean before committing
flutter run              # device/emulator
flutter build apk --debug
```

- There is **no `test/` directory, no CI, and no lint beyond `flutter_lints`**. `flutter test` fails
  ("no test folder") — don't add it to a verification loop without creating tests first.
- `flutter`/`dart` are **not on PATH in this container**; you cannot run analyze/build here. Verify by
  reading code, and say so instead of claiming a green build.
- Release builds sign with the **debug key** (`android/app/build.gradle.kts`); no flavors exist.

## Setup gotchas

- `lib/config/supabase_config.dart` is **listed in `.gitignore` but still tracked**. `git add` of your
  edits is silently skipped — use `git add -f` if you must change it. It currently holds a real
  project URL + anon key, so `main.dart`'s "is Supabase configured?" check
  (`SUPABASE_URL != 'YOUR_SUPABASE_URL'`) always passes and sync is live in a fresh clone.
- `android/gradle.properties` hardcodes `org.gradle.java.home=C:/Program Files/...` (Windows). Change or
  remove it before any Android build on Linux/macOS. `android/local.properties` is absent and is
  generated by the Flutter tool (needs `flutter.sdk`).
- `lib/models/models.dart` is **dead code** (no imports). The live models are in `lib/models/local_models.dart`.
- `lib/services/supabase_service.dart` is mostly **legacy** (expenses/savings_goals/rewards APIs that do
  not match the current backend); only `initialize()` and `getCurrentUser()` are actually used.
  The real sync path is `sync_service.dart` + `sync_mapper.dart`.
- `README.md` and `lib/config/SUPABASE_SETUP.md` are **stale** (they describe Isar-era layout,
  `lib/cqrs/handlers.dart`, `local_user_migration.dart`, and a rewards/expenses schema that no longer
  exists). Trust `supabase/schema.sql` + `supabase/migrations/*.sql` and the code.
- `lib/config/category_icons.dart` is a ~53k-line / 1.6 MB icon catalog. Don't read, reformat, or
  bulk-edit it; add entries instead.

## Architecture (what actually runs)

```
screen → cqrs.bus.execute(command) / bus.query(query)
       → lib/cqrs/handlers_sqlite.dart   (write to SQLite + enqueue outbox, in one transaction)
       → lib/services/sync_service.dart   (pushes outbox → Supabase, pulls remote snapshot)
```

- `lib/services/cqrs_service.dart` is the **registration point**: every new command/query must be
  registered there, or the bus throws `StateError('No command handler registered for ...')`.
- Screens call `CqrsService.create()` themselves (new bus + new handler instances each time); the
  SQLite handle is shared via the `LocalDb.instance` singleton. Do not assume handler state persists.
- `lib/main.dart` boots: open DB → `TimestampRepairService` → `AccountBalanceRepairService` →
  (background) Supabase init + `SyncService.initialize`. Startup is guarded by a 1.1 s splash delay.

### Local DB rules (`lib/services/app_database.dart`)

- File `financetracker.sqlite` in the app documents dir. **`_dbVersion = 1` and there is no
  `onUpgrade` callback** — only `onCreate`. Adding a column/table requires bumping `_dbVersion` *and*
  adding an `onUpgrade` migration, otherwise existing installs silently keep the old schema (or fail).
- **Soft deletes**: set `deletedAt`; all reads filter `deleted_at IS NULL` (`deletedOnly: true` fetches
  the deleted rows). Never hard-delete.
- Timestamps are **ISO-8601 UTC strings**; `TimestampRepairService` normalizes legacy local-time
  timestamps left over from the Isar era. Store new timestamps in UTC.
- **Render every stored date in local time.** `lib/utils/date_time_utils.dart` (`AppDateTime`) is the
  single place for that: `AppDateTime.formatTime/formatMediumDate/formatLocalDateTime`. Entities are
  loaded as UTC, so formatting them without `toLocal()` shows UTC on screen (this was a real bug on
  the home cards vs. the edit form). When editing, load `entity.date.toLocal()` into the picker and
  send the local `DateTime` back — handlers call `toUtc()` when persisting, so the instant is stable.
- `current_balance` is maintained **incrementally** by handlers and then recomputed from
  `opening_balance` + transactions/transfers by `AccountBalanceRepairService` (tolerance 0.005) at
  startup and after sync. If you add a money-moving path, keep both consistent.
- `summary_cache` is **derived data**: transaction handlers call `SummaryCacheWriter.rebuildForDate`,
  which rebuilds weekly/monthly/yearly/lifetime rows. Don't write it by hand.

### Sync rules

- Every write path must enqueue a `sync_outbox` row (`SyncOutboxWriter.enqueue*`) **inside the same
  transaction** as the local write, then call `SyncService.instance?.requestSync()`. Missing the
  outbox row means the change never reaches Supabase.
- Local primary keys are `account_id`/`category_id`/... but the **remote schema uses a single `id`
  column** (`supabase/schema.sql`); `SyncPayloadMapper` does that renaming. Remote upserts use
  `onConflict: 'id'`. New entity types need: local entity + `toMap`/`fromMap`, DB table + put/get,
  a `SyncPayloadMapper` method, a remote table, and handler registration.
- Remote schema is applied manually: `supabase/schema.sql` (base tables) then
  `supabase/migrations/<timestamp>_<name>.sql` (bucket + credentials tables, RLS policies).
- Profile photos upload to the Supabase storage bucket `profile-photos`
  (`lib/screens/personal_information_screen.dart`).

### Exports

- `lib/services/export_service.dart` turns a list of `ExportEntry` into a PDF (`pdf` package) or an
  XLSX workbook (`excel` package), writes it to `<documents>/exports/`, and opens the platform share
  sheet (`share_plus`). The transaction history screen owns the filter→`ExportEntry` mapping.
- Version constraints matter: `excel` needs `xml < 7.0.0`, so `pdf` must stay on `^3.12.0`
  (`pdf 3.13.x` requires `xml 7.x`). `share_plus` needs `web ^1.0.0`, which forces `web_socket_channel`
  to 3.x. `flutter pub get` will bump `xml`/`dbus`/`web` in the lock — expect lock churn.

### Identity

- There is **no real auth**. `UserIdentityService` hardcodes a single local user id
  (`_fixedUserId` in `lib/services/user_identity.dart`); email/display name are editable SharedPrefs.
  Every query is scoped by that id. Don't add a login screen without designing multi-user scoping.

## UI conventions

- Dark mode only, `useMaterial3: false`, Inter via `google_fonts` (fonts are fetched at runtime, not
  bundled). Use the `AppColors` constants in `lib/config/app_colors.dart`; the palette is defined in
  `DESIGN.md`.
- **No green for income** — positive amounts use `AppColors.incomePositive` (violet/lavender).
- Route names live in `lib/config/app_routes.dart`; `main.dart` registers them in `MaterialApp.routes`.
  Main tabs (Home / Dashboard / Credentials / Profile) are switched in `MainNavigation` in `main.dart`,
  not via routes.
